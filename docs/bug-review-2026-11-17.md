# Review of reported B1–B9 issues

Reviewed against the current checkout on 2026-11-17. No Gemini calls or whole-video timing runs were made for this review. Existing unrelated workspace changes were preserved.

| Finding | Verification | Action |
|---|---|---|
| B1: strict/non-strict translation cache breaks OPUS overlap | **Not reproduced for the supported OPUS path.** `OpusMTTranslator` implements `translate_batch`, not `translate_cues_batch`. Strict prompt-batch keys apply only to the contextual cue backend. Config currently disallows English overlap with contextual LLM translators. | Worker now passes `strict_context_cache=True` explicitly for consistency. Added a regression using the actual OPUS class with only inference stubbed; prefetch across two regions then final strict translation makes zero extra translation calls. No claim that this flag change accelerates current OPUS. |
| B2: editing one cue invalidates the rest of OPUS | **Incorrect backend attribution.** OPUS caches dialogue groups. Contextual LLM prompts include whole batches and translated history, so their wider invalidation is intentional for correctness. A batch size of 120 belongs to `_ChunkedTranslator`, not OPUS. | Clarified the pipeline comment. Regression verifies editing one independent OPUS cue causes exactly one extra translation call. Joined dialogue can intentionally invalidate both members. |
| B3: unexpected exception loses failed auto report | **Confirmed.** Only `JellyDubError`/`OSError` were recorded. | Record ordinary `Exception`, then re-raise the original. KeyboardInterrupt/SystemExit remain unhandled. Added KeyError, ValueError and RuntimeError regressions. |
| B4: finish waits forever | **Confirmed.** Worker drain called `wait()` without a deadline. | `finish(timeout=600)` defaults to a finite ten-minute drain; timeout reports the failure, terminates the worker process group, escalates to SIGKILL after ten seconds and uses standard fallback. Regression uses a real sleeping subprocess with a short deadline. This bounds drain, not total pipeline runtime or arbitrary blocked submit writes. |
| B5: benchmark crashes on empty samples / hides sampler errors | **Confirmed.** `max()` had no empty default, and sampler thread failure was not reflected in the report. | Empty peak RSS is null, sampling failure marks the run failed and returns nonzero. Capture sampler exceptions; write preliminary and failed-launch reports; capture ordinary stream/runner failures. Tests cover an empty sampler and an exception in its thread. |
| B6: trace tool silently skips malformed/unmatched events | **Confirmed.** Unknown end events were skipped and JSON errors lacked a controlled failure report. | Validate event schema, finite timings, unique pairing, phases, statuses and completion. Invalid JSON, orphan/duplicate events, empty and unfinished traces fail with a line-specific error where applicable, failed summary JSON and nonzero CLI exit. Existing Family Guy trace passes the stricter reader. This cannot detect an entire missing begin/end pair without an external event inventory. |
| B7: SDK rejects threads=0 | **Not reproduced with installed SDK.** Installed `vieneu/v3turbo.py` declares `threads: int = 0`; factory forwards kwargs. | Default zero is now omitted to allow SDK defaults and older signatures; positive overrides still pass explicitly. Strict-signature regression verifies omission; existing CP1 test verifies threads=3 forwarding. No inference model was loaded to verify this signature. |
| B8: atomic write uses shared .part filename | **Confirmed.** Simultaneous unlocked writers could replace/remove each other's temporary file. | `atomic_write_bytes/text` use unique mkstemp siblings and clean up on failure. Concurrent-writer regression forces both writers to reach replacement together. Last writer wins intentionally; atomic replacement does not serialize logical read/modify/write transactions. |
| B9: legacy import mutates source metadata without source lock | **Confirmed.** `_cached_duration(candidate)` could create metadata in another job. | Read/validate legacy candidates without adopting metadata. Only the imported target gets its metadata under the target lock. Regression verifies source metadata remains absent and target metadata exists. |

These findings do **not** establish that previous 51–111 s queue-drain intervals were wasted translation. Drain can include remaining useful translation/TTS work. A new trace or backend-specific call evidence is necessary before attributing that time or promising speed improvements. The previous Gemini run's HTTP 429 failures remain quota failures; no quota retry policy was changed here.
